# План реализации Daily Pass

## Цель и границы
Минимальный PHP 8.3 сервис и самостоятельный mock оператора, MySQL 8, Composer/PHPUnit, запуск одной командой `docker compose up --build`. Без Yii2: для пяти сценариев достаточно небольшого HTTP-слоя и явно разделённых классов. Не реализуем auth/SSO, USSD, DLR, баланс, несколько валют и production-инфраструктуру.

## Порядок работы
1. Создать Docker Compose, автоматическую генерацию локальных секретов, healthchecks и версионированную миграцию.
2. Реализовать конфигурацию, валидацию, HTTP-клиент оператора и хранение подписчиков, платежей, попыток, webhook-событий и SMS outbox.
3. Реализовать opt-in, webhook и STOP с сериализацией операций по подписчику. Alias хранится как непрозрачный идентификатор; SMS-адрес отделён от него.
4. Реализовать биллинг: уникальность `(subscriber_id, billing_day)`, детерминированный ключ, сохранение PROCESSING до сетевого запроса, классификация ошибок, ограниченные повторы с backoff.
5. Создать persistent mock: настройка кодов и последовательностей ответов, реальные HTTP callbacks, журнал SMS/списаний, симуляция потери ответа и задержки.
6. Покрыть PHPUnit-тестами денежные сценарии, включая параллельные процессы, рестарт, неопределённый результат, повтор webhook и STOP.
7. Проверить сборку/запуск Docker, выполнить тесты, описать curl-сценарии и ограничения в README/DECISIONS.

## Денежные инварианты
- Один логический платёж на абонента и день UTC; ключ SHA-256 от namespace, subscriber ID и даты, одинаковый для всех попыток.
- PROCESSING и запись попытки фиксируются до HTTP. Оставшийся после аварии PROCESSING становится UNKNOWN, автоматического повторного списания нет.
- S1000 с подтверждённым referenceId → SUCCEEDED и SMS outbox в одной транзакции. E1337 не доказывает успех → UNKNOWN.
- E1326/E1318 → не более трёх попыток с backoff; E1308 → FAILED_PERMANENT и SUSPENDED. Неизвестные ответы/транспортные ошибки → UNKNOWN.
- Биллинг, lifecycle и callbacks используют одну MySQL advisory lock на абонента и короткие транзакции с row locks. Она держится на время вызова оператора: STOP, завершившийся раньше биллинга, исключает списание. Уже отправленный оператору debit невозможно отменить; это явно документируется.
- UNKNOWN блокирует дальнейшие автоматические списания абоненту до внешней сверки.
- Outbox переживает сбой после фиксации успеха; доставка SMS at-least-once, поскольку оператор не предоставляет SMS idempotency key.

## Проверка результата
Автоматические проверки выполняются против реального MySQL и HTTP mock внутри Compose. Проверяем число фактических списаний, состояние БД, стабильность ключей, аудит попыток и наличие/отсутствие квитанций. Также проверяем валидацию, masked alias, stale callbacks и повторный opt-in. Если окружение не позволяет выполнить Docker, отдельно фиксируем фактически выполненные проверки и оставшийся пробел.

## Результат реализации
Созданы сервис, persistent mock, миграция, Docker Compose, lock-файл Composer, PHPUnit-тесты и документация сценариев. Денежные и HTTP-сценарии проверены с реальным MySQL 8 и отдельными процессами воркеров. Подробные результаты и открытая проверка Docker зафиксированы в `VERIFICATION.md`; сборка через Docker не объявляется проверенной при недоступном Docker API.
